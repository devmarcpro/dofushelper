# Feuille de route — jalon M3 (interface MVP)

Rédigée par l'agent le 2026-09-19 sous carte blanche de Marc, à partir de `docs/SPEC.md` §3, §8, §9, §11 et §12. Mode boucle : le plan est annoncé puis exécuté ; chaque étape se termine par typecheck, lint, tests, build, commit, push et mise à jour de `docs/PROGRESS.md`.

Cadre : Preact + `@preact/signals`, CSS natif, routeur hash minimal, aucune nouvelle dépendance runtime, JS initial ≤ 80 Ko gzip hors données, textes dans `src/ui/strings.fr.ts` sans concaténation de phrases, cases à cocher natives, focus visible, 380 px d'abord. Le navigateur ne charge que `public/data/*` via `src/data/paths.ts`. L'état dérivé n'est jamais stocké : l'UI appelle `createEngine(dataset).resolve(goal, character)` à chaque changement.

**Ordre.** M3-1 → M3-2 → M3-3 → M3-4 → M3-5 → M3-6 → Revue.

## M3-1 — État et persistance (`src/state`)

`AppStateV1` (SPEC §8), `ProgressStore` en interface avec une implémentation `localStorage` (clé `roadbook:state:v1`, écriture différée) et une implémentation mémoire pour les tests, validation à la lecture (état illisible : jamais écrasé, export brut proposé), migrations pures par saut de version, export et import JSON avec fusion « le plus récent gagne » par personnage, un niveau d'undo sur la progression, actions pures (créer, modifier, supprimer un personnage, cocher, décocher, inventaire, choix, objectifs). L'horloge et le générateur d'identifiants sont injectés.
Critères de sortie : réducteurs et sérialisation testés sans DOM ; import d'un export = état identique ; un état corrompu n'est jamais écrasé ; undo restaure l'état précédent.

## M3-2 — Dataset, routeur, coquille

`src/data` : chargement du manifest puis des fichiers, validation minimale, erreurs lisibles, mise en cache en mémoire. Routeur hash (`#/`, `#/objectifs`, `#/plan/<goal>`, `#/fiche/<nœud>`, `#/personnages`). Coquille : en-tête avec personnage actif, navigation, pied de page avec attribution, états de chargement et d'erreur, frontière d'erreur avec export de secours.
Critères de sortie : le site démarre sur le dataset réel ; hors ligne après premier chargement (cache HTTP) ; aucune requête hors `public/data/*`.

## M3-3 — Personnages et catalogue

Écran Personnages (créer, modifier, supprimer avec confirmation, exporter, importer), bascule rapide, écran Catalogue (onglet Dofus au MVP, recherche par nom, progression si déjà suivi), accueil avec barre de progression et prochaine action par objectif, état vide guidé (P1).
Critères de sortie : parcours P1, P6 et P7 réalisables au clavier et au pouce.

## M3-4 — Plan : marche à suivre et choix

En-tête (nom, progression, carte « prochaine action »), onglet Marche à suivre (case, nom, niveau, pastilles donjon / groupe / alignement / événement / critère non interprété, statut, raison de blocage en clair, filtres « masquer le fait » et « seulement le disponible »), message « N quêtes prérequises marquées comme faites · Annuler », nœud déduit verrouillé avec « déduit de : … », onglet Choix (branches, branche retenue, raison, changement).
Critères de sortie : parcours P2, P3, P4 sur le Dofus des Glaces ; réponse perçue < 100 ms.

## M3-5 — Plan : à réunir, conditions, fiche

Onglet À réunir (restant / total, champ « j'en ai », utilisé par, provenance connue : monstres et taux, recette sur un niveau, bascule objets de quête, monstres dont « en un seul combat », donjons), onglet Conditions (niveau, métiers, alignement, classe, contexte et critères non interprétés affichés tels quels avec une phrase d'explication), fiche quête/succès (étapes, objectifs avec balises `{npc,id}` résolues, prérequis, « débloque », récompenses, liens sortants quand ils seront vérifiés), bandeau « données incomplètes » si `plan.issues` n'est pas vide.
Critères de sortie : parcours P5 ; aucune phrase concaténée ; aucun lien deviné.

## M3-6 — Finitions MVP

Passe accessibilité (labels, ordre de tabulation, contrastes AA, `prefers-reduced-motion`), vérification à 380 px sans défilement horizontal, mesure du JS initial, thème clair et sombre, page « À propos / sources », mise à jour du README.
Critères de sortie : SPEC §12 M3 ; « Définition de terminé » de `CLAUDE.md`.
